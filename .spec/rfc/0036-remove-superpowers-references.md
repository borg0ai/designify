# RFC 0036: Remove Residual Superpowers References from Repo Surfaces

**Status:** Approved

## Summary

Finish the designify rebrand on repo-facing surfaces while keeping the Superpowers-derived substance. `.github/` templates, `AGENTS.md`, `docs/`, and test-harness scripts are re-voiced to the designify identity, and every process instruction in them names Specify's RFC lifecycle as the workflow authority. References that denote provenance (origin from Superpowers source) are kept as history. Shipped plugin content under `designify/` is already clean and stays untouched.

## Problem

The rebrand renamed the shipped plugin and packaging, but 38 files still mention superpowers (~2,400 matches). Identity surfaces agents and contributors read first — `AGENTS.md`, `.github/` templates, docs — still speak with the upstream project's identity and process vocabulary, so they instruct agents to follow a workflow model this repo has replaced with Specify. Some leftovers are pure residue (stale paths, a legacy test checking a `skills/` tree that no longer exists). Others carry real value — contribution discipline, harness porting guidance, structural tests — and must be kept, re-voiced, and pointed at Specify.

## Goals

- Identity surfaces (`AGENTS.md`, `.github/` templates, `docs/`) speak as designify; Superpowers appears only as provenance (origin notes), matching the README attribution.
- Every process description on those surfaces names Specify as the lifecycle authority: RFC before code, Approved before implementation, executors consume the approved RFC.
- The README explains why Designify exists: rebuilt from Superpowers source — inspired by Superpowers — with the workflow aligned to Specify.
- Contribution protections are preserved: one problem per PR, evidence of human review, author/model disclosure, no speculative fixes. The upstream `dev`-branch targeting rule is dropped; this repo works on `main`.
- Harness porting docs and structural tests are kept and re-voiced; the dead `tests/diagnosing-superpowers/` check is repointed at the current plugin layout rather than deleted.
- Test-harness scripts keep working: renamed references, valid paths, lint-clean shell.

## Non-goals

- Erasing provenance: historical RFCs, the ReasonGraph why-pack, README attribution, and origin notes in docs/AGENTS.md keep their Superpowers mentions.
- `.birdify/` generated artifacts: they hold birdify-reviewed constraint data and are regenerated by the birdify workflow, not hand-edited; handled separately.
- Shipped plugin content under `designify/` (already zero matches) — no behavior change to skills, hooks, or packages.
- Upstream-repo-specific URLs (prime-radiant-inc, superpowers-evals) are neutralized to plain origin references, not preserved as live links.

## Design

Re-voice and re-align in five task groups. Every edit is prose or test-script naming; nothing changes runtime behavior of the plugin.

### Task 1: Re-voice `.github/` templates

Rewrite `.github/PULL_REQUEST_TEMPLATE.md` and the four issue templates (`bug_report.md`, `diagnosis_report.md`, `feature_request.md`, `platform_support.md`) as designify's. Keep: one problem per PR, real-problem requirement, evidence of human review, author/model disclosure, harness test table, the new-harness acceptance transcript requirement. Replace superpowers process vocabulary with Specify's lifecycle (RFC delivered and validated via Specify; implementation only from an Approved RFC). Replace upstream URLs with a plain origin note. Drop the upstream rule that PRs must target a `dev` branch — this repo works on `main`.

### Task 2: Re-voice `AGENTS.md`

Rewrite as designify's contributor guide, keeping the full structure and discipline: agent protection rules, PR requirements, what-not-to-accept list, new-harness support with the acceptance test, skill-change evaluation bar, eval-harness pointer. Changes: the workflow authority throughout is Specify (RFC before code, Approved before implementation); the eval harness reference stays as an origin pointer; upstream statistics are re-voiced as this repo's standing rules; keep the reasongraph section. Superpowers appears only in an origin note matching README's attribution.

### Task 3: Re-voice `docs/`

In `docs/porting-to-a-new-harness.md`, `docs/testing.md`, `docs/README.kimi.md`, `docs/README.opencode.md`: rename this project's identity to designify, update workspace paths (`.superpowers/` → `.designify/`) and skill entry names, and make Specify the named planning authority where these docs describe process. Keep provenance mentions and upstream harness history as origin notes.

### Task 4: Re-voice `tests/` harness scripts, repoint the legacy structure check

Rename superpowers references across `tests/` scripts (`explicit-skill-requests/`, `claude-code/`, `hooks/`, `antigravity/`, `shell-lint/`) to designify names and current paths; keep the scripts runnable and lint-clean. Repoint `tests/diagnosing-superpowers/` to the current layout: rename it to `tests/diagnosing-agent-behavior/` and check `designify/skills/designify/workflows/diagnosing-agent-behavior/workflow.md` (exists, word budget, no stale paths) instead of the removed `skills/diagnosing-superpowers/SKILL.md`.

### Task 5: Clean `.gitignore`

Remove the legacy `.superpowers/` entry (`.designify/` is already ignored and stays).

### Task 6: Explain the rebuild in `README.md`

Add an "Inspiration" section near the top of `README.md` stating why Designify exists: it is rebuilt from Superpowers source — inspired by Superpowers' workflow techniques — with the lifecycle aligned to Specify (RFC before code, Approved before implementation). Expand the existing one-line attribution into this note; the rest of the README structure stays.

## Acceptance

- `grep -ri superpower` reports matches only in: `.spec/rfc/**`, `.reasongraph/why/**`, `.birdify/**`, `README.md` (Inspiration/origin section), and explicit origin notes in `AGENTS.md`/`docs/` (each a single labeled provenance mention).
- No rewritten surface requires PRs to target a `dev` branch; `main` is the working branch.
- Every process instruction on the rewritten surfaces names Specify (RFC lifecycle) as the authority; no surface describes brainstorming/plans/TDD as a competing lifecycle.
- `pnpm test` passes; renamed repointed scripts pass `scripts/lint-shell.sh`.
- `designify/` remains zero-match.
- Specify `validate` and `sync-check` pass; the RFC advances to Implemented and is archived.
